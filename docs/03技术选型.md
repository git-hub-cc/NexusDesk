基于你明确的要求——**技术栈必须具有唯一性，且以 Tauri 为核心**，我为你量身定制了这套完整的技术选型。

这套选型严格围绕**“构建一个高性能、复杂交互、对标 IntelliJ IDEA 的桌面级应用”**这一目标，摒弃了所有不适合重度桌面端开发的技术，确保后续 AI 辅助开发时不会产生歧义。

### 核心技术栈全景图 (The Definitive Stack)

#### 一、 基础框架层 (Foundation)
*   **核心框架**: **Tauri 2.0** (目前最新版，支持更好的 IPC 和多窗口管理)
*   **前端构建工具**: **Vite** (极速热更新，Tauri 官方推荐)
*   **开发语言**: **Rust** (后端) + **TypeScript** (前端，必须开启严格模式 `strict: true`)

#### 二、 前端视图层 (Frontend - UI & UX)
*   **UI 框架**: **React 18**
    *   *唯一性理由*: 构建类似 IDE 的复杂面板、多标签页、虚拟化长列表，React 的生态（特别是复杂拖拽和代码编辑器封装）是目前前端领域最成熟的，没有之一。
*   **状态管理**: **Zustand**
    *   *唯一性理由*: 相比 Redux 更轻量，相比 Context API 性能更好。完美支持在 React 组件外部读取状态（这对于处理 Tauri 的全局快捷键和底层事件监听至关重要）。
*   **UI 组件与样式**: **Tailwind CSS** + **Radix UI (无头组件)**
    *   *唯一性理由*: IntelliJ 的 UI 非常独特，使用现成的组件库（如 AntD/MUI）会显得像个网页。Radix UI 提供底层逻辑（如右键菜单、下拉框、弹窗），Tailwind CSS 负责像素级复刻 IntelliJ 的 Darcula (暗色) 和 Light 主题。
*   **IDE 布局引擎**: **react-resizable-panels**
    *   *唯一性理由*: 这是 React 社区最强大的可拖拽分割面板库，完美实现 IntelliJ 左侧目录、底部 Git 面板、中间编辑器的自由拖拽缩放。

#### 三、 核心功能组件 (Core Features)
*   **Markdown 编辑器内核**: **CodeMirror 6**
    *   *唯一性理由*: 既然对标 IDE，编辑器必须是“代码级”的。CodeMirror 6 性能极高，支持超大文档，且其底层的 State/View 架构允许我们深度定制**“拖拽生成双链”**的交互（通过自定义 Widget 和 Decoration）。
*   **目录树组件**: **react-arborist**
    *   *唯一性理由*: IntelliJ 的目录树需要支持上万个节点、虚拟化滚动、拖拽移动、行内重命名。react-arborist 是目前 React 生态中唯一能完美满足这些重度桌面端需求的树形组件。
*   **复杂拖拽系统**: **dnd-kit**
    *   *唯一性理由*: 用于实现标签页（Tabs）的拖拽排序、左右分屏的拖拽，以及你提到的“将文件拖入性质模式目录”。

#### 四、 后端逻辑层 (Rust Backend - 性能与底层)
*   **本地数据库 (索引与逻辑视图)**: **SQLite (通过 `rusqlite` 库)**
    *   *唯一性理由*: 你的“性质模式（逻辑目录）”不能每次都去遍历物理文件。Rust 后端需要在后台解析 Markdown 的元数据/标签，存入 SQLite。前端的逻辑目录树直接从 SQLite 查询生成，保证毫秒级响应。
*   **全文搜索引擎**: **Tantivy**
    *   *唯一性理由*: IntelliJ 的核心竞争力是极速的全局搜索（Double Shift）。Tantivy 是 Rust 编写的搜索引擎（对标 Java 的 Lucene），能为你的笔记提供 IDE 级别的秒级全文搜索。
*   **Git 底层集成**: **git2-rs**
    *   *唯一性理由*: 这是 libgit2 的 Rust 绑定。不要通过命令行去调用 Git（容易出错且性能差），使用 git2-rs 可以直接在内存中操作 Git 仓库，完美实现 IntelliJ 风格的 Commit 面板和 Log 历史树。
*   **文件系统监听**: **notify**
    *   *唯一性理由*: 当用户在外部（如资源管理器）修改了文件，软件内部的目录树必须瞬间同步。notify 是 Rust 最好的跨平台文件系统监听库。

```markdown
# 项目全局设定：NoteIDE (基于 Tauri 的 IDE 级笔记软件)

## 1. 技术栈强制约束 (Strict Tech Stack)
- **核心**: Tauri 2.0 + Vite
- **后端**: Rust (Cargo)
- **前端**: React 18 + TypeScript (Strict Mode)
- **状态管理**: Zustand
- **样式与UI**: Tailwind CSS + Radix UI + lucide-react (图标)

- **编辑器**: CodeMirror 6 (用于 Markdown 源码编辑与双链交互)
- **目录树**: react-arborist (支持虚拟化与拖拽)
- **后端核心库**: rusqlite (元数据索引), tantivy (全文搜索), git2 (Git集成), notify (文件监听)

## 2. 核心设计原则 (Design Principles)
- **UI/UX 严格对标 IntelliJ IDEA**: 包含侧边栏工具窗口 (Tool Windows)、顶部多标签页 (Tabs)、底部状态栏。
- **物理与逻辑分离**: 
  - 物理视图 (Project View): 映射真实 OS 文件夹。
  - 逻辑视图 (Nature View): 基于 SQLite 索引的虚拟目录树。
- **性能优先**: 所有耗时操作（文件遍历、Git 状态检查、全文索引）必须在 Rust 后端异步执行，通过 Tauri IPC 传递给前端，前端只负责渲染。

## 3. 关键交互逻辑 (Key Interactions)
- **双链拖拽**: 在 CodeMirror 中输入 `[[` 触发关联模式，支持通过鼠标拖拽连接到另一个分屏的标题，生成锚点链接。
- **全局快捷键**: 必须在 Tauri 层面或 React 全局监听，实现类似 IntelliJ 的 `Double Shift` (全局搜索), `Ctrl+E` (最近文件) 等。
- **Git 面板**: 独立的 Tool Window，调用 Rust `git2` 接口，实现类似 IDEA 的 Local Changes 和 Log 视图。
```

### 为什么这套选型能成功？
1.  **规避了 Electron 的内存黑洞**：Tauri + Rust 保证了软件启动速度极快，内存占用极低，这对于常驻后台的笔记软件至关重要。
2.  **解决了“逻辑目录”的性能瓶颈**：通过 Rust + SQLite 在底层建立索引，前端的“性质模式”切换将是瞬间完成的，即使你有上万篇笔记。
3.  **为“拖拽双链”提供了底层支持**：CodeMirror 6 的架构允许你获取到精确的 AST（抽象语法树）节点位置，这是实现“拖拽指向特定标题”这一创新交互的技术前提。
